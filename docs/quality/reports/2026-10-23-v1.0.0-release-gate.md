## 3. Known defect shipped in this release

### #95 — web icons shipped as base64 text; manifest declares a missing file

The four PNGs under `web/` were committed as base64 **text**, and
`manifest.json` declared `icons/Icon-maskable-512.png`, which was never added.
Confirmed **in production**, not inferred from the repository:

| Asset | Live result |
|-------|-------------|
| `/favicon.png` | HTTP 200, **1,224 B starting `iVBORw0K`** — base64 text, not a PNG |
| `/icons/Icon-192.png` | HTTP 200, **7,054 B starting `iVBORw0K`** — base64 text |
| `/icons/Icon-maskable-512.png` | **HTTP 404** |

Player impact: broken favicon and install icons, a 404 on every load, and no
install prompt. Gameplay is unaffected — this is a web-shell defect only.

**Disposition:** known and accepted for `v1.0.0`. Fixed on `develop` by PR #97
(`50121d4`, "fix(web): ship real PNG icons and a valid manifest"), which is not
part of this release and ships in the next one. Recorded in the release notes
with a pointer to the fix, per OPS-10's acceptance criteria.

**Why it reached production.** Every base64 file decodes to a valid image, so
the artwork was correct and only the encoding on disk was wrong. Nothing in the
suite could see it, and — importantly — **the smoke suite's step 10 did not
catch it either**. That step passed on `main` while the live site served
base64 icons and a 404 manifest icon, because browser-level manifest and image
fetch failures are not delivered to the page's console session. Coverage for
this class now comes from `test/web_assets_test.dart`, which fails **3/3** on
`6c21684` and passes after PR #97.
