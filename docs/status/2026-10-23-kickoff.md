## 5. Recommended first iteration

If the user wants the smallest set that materially improves release safety:

1. **OPS-1** — pin the toolchain (reproducible builds).
2. **OPS-3** — build the web artifact on PRs (catch deploy-breaking errors).
3. **QE-1** — automate the release smoke path.
4. **OPS-10** — tag v1.0.0 so the deployed release is traceable.
5. **PM-1 / UX-1** — start product and design discovery in parallel.

This gives the team a trustworthy release gate before the next feature ships.

1. User triages a subset into **Ready**.
2. Developers create one worktree per task and implement in priority order.
3. QE verifies each PR and writes the verdict.
4. Project Manager prepares the release; DevOps deploys and verifies production.
5. Project Manager reports progress in `docs/status/`.
